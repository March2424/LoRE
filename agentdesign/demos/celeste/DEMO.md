# Celeste 英译简中演示路线

用《蔚蓝》Steam 本地资源做英译简中。先导入真实英文，再沿一条图谱证据和一条复核任务走到 CSV 交付。离线演示使用固定模型回执，便于每次复现通过、修复和人工接手三种路径。

## 演示前准备

在 `agentdesign` 的 PowerShell 中运行。依赖已安装时可从生成数据开始。

```powershell
uv venv --python 3.14 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements-api.txt
npm.cmd --prefix pi ci
npm.cmd --prefix web ci
npm.cmd --prefix web run build
python demos/celeste/build_dataset.py
.\.venv\Scripts\python.exe demos/celeste/verify_demo.py --serve
```

启动后等终端打印 `Celeste API acceptance`，然后打开 [LoRE 工作台](http://127.0.0.1:8766/) 或 [API 文档](http://127.0.0.1:8766/docs)。界面默认英文，演示时可用侧栏语言开关切成中文。端口被占用时可给最后一条命令加 `--port 8767`。每次运行默认使用独立的 SQLite 工作目录，终端会打印报告位置和任务 ID。Steam 安装位置不同的机器可给生成命令加 `--game <Celeste 安装目录>`。

## 六分钟走查

| 时间 | 演示操作 | 观众可以核对 |
| --- | --- | --- |
| 0:00–1:00 | 选「Celeste · EN → 简体中文 · 离线演示」，进入「工作台」。在源条目中按键名搜索 `MENU_BEGIN`、`POSTCARD_AREA_2` 或 `CH9_FAREWELL`。 | 同一个四列 CSV 覆盖界面、教程与收藏品、剧情与多说话人对白。资源 ID 沿用游戏键名。 |
| 1:00–2:30 | 打开「图谱与记忆」，依次查 `Badeline`、`Strawberries`、`Celestial Resort Hotel`。点关系或来源引文。 | Badeline 与 Madeline 的 `PART_OF`、草莓的物品定义、旅馆停业公告各有原文位置。可再查 `my sister`，用 Theo 的台词说明亲属关系如何作为证据展示。 |
| 2:30–4:00 | 在「任务」打开终端所示的翻译任务。找到 `AREA_CHAPTER`，查看「审校结论」中的修复与通过。 | 初稿漏了 `{x}`，修复后的译文保留变量。并列展示 `MENU_BEGIN` 的直通过程。 |
| 4:00–5:15 | 回「工作台」，点 `celeste-en-zh.csv` 的待复核数字，打开原文 `Clear`。结合章节完成场景，输入「通关」，填写原因并点「批准译文」。 | 短词歧义进入文件复核队列，编辑确认后进入批准记忆。 |
| 5:15–6:00 | 在「工作台」的「文件进度与检查导出」中打开该文件的「检查与导出」，下载原格式文件和报告。 | `translation` 列写回批准内容。可按 `id` 对照导出值，报告能定位未交付条目。 |

工作台里可在「图谱与记忆」查看批准记忆。演示准备脚本已走过序幕 `CH0_INTRO` 的错误提交和更正，现场可查对应任务证据。需要再次演示待复核时，重跑准备脚本会创建新的工作目录和任务。

## 数据与评测范围

- 数据来自 Celeste Steam App `504230` 的 `Content/Dialog/English.txt` 和 `Simplified Chinese.txt`。`manifest.json` 记录 Steam build、源文件 SHA-256、记录类型和简中重复键位置。简中同名键按最后一次赋值取参考。
- 533 条由游戏本地化键构成，包含 227 条 UI、143 条对白、23 条叙事、17 条水晶之心收藏提示、31 条教程，以及 92 条名称、章节、检查点和致谢。对白键可包含整段交互和多个说话人，因此规模以键计。
- `celeste-en-zh.csv` 只有 `id,source_text,text_type,context`。`context` 提供英文原生段落、角色标记和注释。变量、控制符、对白行和内部换行保留。`references.jsonl` 保存官方简中以及两侧源行号，供评测使用。生成文件放在 Git 忽略的 `runs/celeste-demo/dataset`。
- 仓库附有 Steam build `17282758` 的 [533 条数据索引](record-index.csv)、[来源与校验值](steam-17282758.json) 和 [验收数据](offline-acceptance.json)。索引包含条目 ID、类型和双语文件行号。完整英文 CSV 和官方简中参考从各自的游戏安装本地生成。相同 Steam build 可用 `Get-FileHash` 对照清单中的数据哈希。
- 物品信息主要来自草莓提示、统计、收藏文本和对白。该数据覆盖已有的本地化资源。关卡物件清单、时序与完整剧情分支条件需要地图或运行时资料。当前图谱用 `PART_OF` 表示 Badeline 与 Madeline 的关系。Theo 的亲属信息由对白中的两条边与引文支持。

## 评测

| 类型 | 样本 | 参考结果或判定规则 |
| --- | --- | --- |
| 常见成功 | `MENU_BEGIN` | 简明的攀登动作标签，官方参考为「攀登」。 |
| 格式故障与自动修复 | `AREA_CHAPTER` | 删除 `{x}` 的固定初稿应失败，修复稿须精确保留 `{x}`。 |
| 语义歧义 | `MOUNTAIN_COMPLETE_NORMAL_FULLCLEAR` | 在章节完成界面应表示通关，固定初稿「清除」须进入待复核。 |
| 交付门禁 | `CH0_INTRO` | `{+MADELINE}` 是玩家名引用，固定人名稿须返回 HTTP 422。恢复引用和三行版式后可批准交付。 |
| 人物与剧情 | `CH2_BADELINE_INTRO`、`CH6_THEO_SAY_TRUST`、`CH3_MEMO` | 判断 Badeline 自述与 Madeline 的关系、Theo 对妹妹的提及、旅馆停业的剧情事实。图边必须有原文证据，审阅时核对说话人与叙述者。 |
| 物品与控制符 | `POSTCARD_AREA_2`、`POEM_CSR` | 草莓是游戏收藏品，后者按水晶之心标题语境评估「金羽毛」。评阅保留控制符，并区分原文术语和参考侧排版差异。 |
| 条件性上下文 | `CH2_THEO_INTRO_NEVER_MET` | 保留首次相遇语境，人物关系和叙事判断须遵守原生条件注释。 |

### 指标与对照

实际离线对照把同一批固定初稿分别按「直接采用初稿」和「经 LoRE 硬检查、Pi 固定审校、最多一次修复」评估。报告记录严格参考命中数、逐条预期状态命中数、错误批准的 HTTP 状态和最终交付行数。建图对照使用相同导入和同一项目，先发结构快照，再通过真实图谱校验器写入预先标注的固定实体和边。图谱指标看成功发布的实体和边，以及边是否可定位至原始 CSV 行。

### 本机验收记录

2026-11-23，Steam build `17282758`，LoRE `1442783`，Python 3.14.7、Node 25.9.0、FastAPI 0.115.14。图谱批大小 24、实际固定回执 24 批、每批输入预算 16,000、输出预算 2,048，翻译任务总调用预算 24，最多修复一次。记录和交付样本随每次运行写入 `acceptance.json` 与 `approved-export.csv`。

| 实测项 | 结果 |
| --- | --- |
| CSV 导入预检与确认 | 预检新增 533 条，确认后资源库共 533 条，批准记忆从 0 开始。 |
| 图谱 | 结构快照为 533 节点、0 边。固定关系快照为 540 节点、7 边，查询验证了人物、物品、场景和亲属提及的来源位置。 |
| 四条翻译用例 | 直接取初稿时严格参考命中 1/4。经审校与修复、人工介入前命中 2/4，四条预期状态全部命中。 |
| 人审及导出 | 序幕的无变量稿返回 HTTP 422。更正后共 3 条获批并写入 CSV。`Clear` 仍保留在队列，供现场操作。 |
| 官方参考过门禁 | 512/533 通过，21 条触发规则，含 20 条标签差异、2 条物理换行差异及 1 条 Naev 控制符差异，类别有重叠。 |

官方简中有语言专用排版。例如 `JOURNAL_SPEEDRUNS` 会调整 `{n}` 的使用，英文控制符完全一致的规则会拦下这类参考。`CH5_THEO_MIRROR` 还触发当前沿用的 Naev 控制符检查。评测时把这些样本交给人核对，单独统计运行安全和语言质量。

### 在线评测复现

本机验收使用固定回执，环境缺少 `DEEPSEEK_API_KEY` 或已绑定的兼容模型。真实模型质量、稳定性及独立人工盲评仍待测。配置好仓库支持的模型后，在另一端口启动 `run_api.py --projects-only`，为两个独立英译中项目分别导入相同 CSV。用模型设置绑定同一模型版本，或使用服务默认模型。A 组建图传 `extract:false`，B 组开启抽取。全量导入按本次预算测得 24 批，建图调用上限据此设置。两个项目用相同的资源键选择同一测试样本，各自在 `/resources` 取实际的 `occurrence_id` 发 `/jobs`，通过任务证据及导出接口保存逐条输出。

采用真实模型时，预先冻结相同的按章节与类型分层小样本，保留上述压力用例，并从其他章节和界面抽普通项。两组使用同一模型和版本、相同的源文和任务指令、同等输出预算与调用次数，批准记忆均从空开始。A 组禁用图谱证据，B 组启用图谱证据，保留相同审核门禁。可加直接草译一列观察审核和修复的贡献。每组独立重复三次，记录实际模型 ID、后端、提示版本、温度或服务端默认值、输出及调用用量。报告各轮范围、逐条失败、进入人工的比率和图边正确率。官方简中只在评测阶段读取。

自动指标包括变量及控制符保存率、图边证据有效率、格式通过率、预期复核召回率与误报率。参考文本完全一致是可复现指标。译法质量采用下表的盲评标准，允许符合语境的合理译法。

| 维度 | 人工或 LLM 判定准则 |
| --- | --- |
| 含义 | 0 为含义或剧情事实错，1 为大意正确但遗漏，2 为含义及剧情关系正确。 |
| 术语与语气 | 0 为关键术语、发话人或称谓错，1 为可理解但语气或术语不稳定，2 为符合角色、术语和界面场景。 |
| 格式 | 逐一核对变量、角色和触发标记，任何影响游戏行为的差异为硬失败。用官方参考的排版差异辅助定位规则误伤。 |
| 人工复核 | 预标需要人审的歧义与不允许交付的硬失败。计算预测和预标的召回率、误报率。 |

如需 LLM 裁判，盲化组名，提供源文、允许的上下文、候选和参考，按上述维度逐项打分并要求引用证据。演示者或译者逐一核对全部压力用例和所有裁判不一致项，并从普通项随机抽查至少 10 条。记录人工裁定、理由和分歧率，抽查人员应独立于模型运行。
