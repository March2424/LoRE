# P5 · 人工反馈与策略回放

在工作台复核条目时，编辑可以填写修改原因。确认操作把原因和实际修改前后的文本写入对应任务的反馈。也可以对已处理的条目直接登记反馈，附上待识别的实体别名和确认拼写。同一条别名出现在两个不同 occurrence 中时，创建候选会默认纳入该映射。候选发起人可以指定具体改动。

| 组件 | 首版支持 |
| --- | --- |
| Prompt | 审校器首次查看源图时的 `reviewer_source` 指令补充，或转人工展示模板。模板使用 `{reason}`，可另带 `{occurrence_id}`。任务状态和审批约束由后端执行。 |
| Memory | 引用 P4 术语预览，在隔离对照中检查拟议术语。正式术语仍走 P4 应用流程。P5 发布时核对该规则已批准且处于当前版本。 |
| Skill | 按 `ambiguity`、`missing_evidence`、`terminology` 或 `context` 限定已有源图审校流程启用查询扩展的情形。 |
| Harness | 对实体名套用确认过的别名映射，并将每次查询返回数设为 1 或 2。沿用原有只读工具、调用次数、快照及作用域。 |

## 接口

启动方式见 [工作台说明](../README.md)。本机 `/docs` 提供可直接填写的接口。反馈写入、发布决定和回滚使用 `Idempotency-Key`。

| 接口 | 操作 |
| --- | --- |
| `POST /feedback` | 传 `job_id`、`step`、`occurrence_id`、`category` 和 `reason`。可传 `after` 作为建议译文。实体反馈可传 `alias`，含 `query` 和 `canonical`。 |
| `GET /feedback` | 查看反馈及重复出现的问题与别名。 |
| `GET /policy` | 查看当前策略和已有候选。 |
| `POST /policy/candidates` | 传 `feedback_ids` 和 `changes`。变更字段是 `prompts`、`handoff_template`、`aliases`、`lookup_results`、`skill_issues` 和 `memory_plan_id`。 |
| `POST /policy/candidates/{id}/replay` | 传 `mode`、`dataset` 和 `cases`。样本用 `job_id`、`step`、`occurrence_id` 定位，可标注 `expected_evidence_ids` 或 `expected_verdict`。 |
| `GET /policy/candidates/{id}` | 查看候选、组件版本、回放报告及决定。 |
| `POST /policy/candidates/{id}/decide` | 传 `decision` 为 `publish` 或 `retain`，同时填写 `reason`。 |
| `POST /policy/releases/{id}/rollback` | 填写 `reason`，为当前发布追加一个恢复前一份配置的版本。术语内容的恢复由 P4 执行。 |

## 回放与发布

- `record` 使用历史工具和审校回执，比较转人工展示并重新执行硬检查。`strategy` 从同一历史草稿与初始 ContextPack 重跑首次 Reviewer 工具查询。默认复用历史处置，单独衡量源图检索变化。真实模式可传 `live: true`，使用历史模型配置重新运行两组首次 Pi 审校，每组至多两次模型请求。
- 回放读取当前工作目录内有完整审校轨迹的任务，核对其源图快照。在临时 SQLite 副本执行工具和术语预览，保留当前人工锁，并把报告写回工作台。P0 / P1 命令行的 JSONL 轨迹保存在各自运行目录。
- `feedback` 只接受候选关联的任务条目。`validation` 按 occurrence ID 和源文件排除已用于该候选的反馈样本。报告含原始与实际查询、证据 ID、命中与缺口解决率、作用域违规、硬规则和转人工结果，以及模型调用数、可用 token 和耗时。策略计时在双方共享的图索引加载后开始。
- 发布要求两组 `record` 均通过。检索、Skill、Memory 或审校指令改动还需要两组 `strategy` 通过。检索或 Skill 改动须在已标注的样本中补到有效证据。审校指令改动须用 `live: true`，两组均需标注预期判定。已发布的策略版本在创建任务时冻结。

## 验收

用冻结 Naev 源图和离线 Pi 回执构造 2 条反馈、2 条独立验证。反馈帮助将 `Emperors Fist` 扩展为 `Emperor's Fist`。在 3 条标注了预期证据的样本中，策略对照从 0 条命中升至 3 条，越界引用为 0。记录回放通过转人工模板对照。独立验证包含人工锁和缺失占位符。额外的 P4 术语候选因新增硬术语问题未通过回放，工作台术语库和译文版本保持原样。测试还覆盖了未验收拒绝发布、发布后新任务使用策略，以及追加回滚。

可用 [验收测试](../tests/test_feedback.py) 重跑。逐条差异、失败报告和发布决定保存在本地 `runs/p5-feedback/acceptance.json`。本轮实际重查本地源图。真实 DeepSeek 策略对照和语义质量尚未验收。
