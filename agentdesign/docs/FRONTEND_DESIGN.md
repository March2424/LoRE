# 游戏本地化 Agent 前端功能设计说明

> **文档定位**：本文档聚焦前端的**功能结构、人工使用流程、人机交互方式及 Agent 自我进化闭环**，不涉及具体视觉风格、配色与样式规范。
> **范围约定**：首版设计优先完整覆盖**当前后端已具备的接口能力**；对于后端尚有局部缺失或未串联的边缘能力，会在对应章节明确标注“当前能力边界与后续扩展项”，不作为首版前置阻塞条件。

---

## 一、 总体功能模块划分

前端将现有单页原型拆分为五个专注的功能区，并配有一个全局可呼出的任务指令栏：

1. **项目与资源管理**：多项目切换、文件导入与字段映射、资源条目筛选、模型配置与可用性检测。
2. **图谱与记忆中心**：分批构建知识图谱、局部图谱浏览、记忆库（术语/角色笔记/译例）查看与草稿审批、术语变更影响维护。
3. **翻译发起与工作台**：界面点选与自然语言指令双通道发起、实时进度跟踪、待补充信息澄清、暂停与补充要求。
4. **人工复核与交付中心**：疑难条目对照改译、Agent 查证依据透明展示、版本锁定与回滚、导出前合规检查与原格式交付。
5. **Agent 进化管理（RSI）**：日常改译反馈采集、问题模式汇总、受控策略微调、沙盒对照回放、发布闸门与版本回滚。

## 二、 模块一：项目创建、文件导入与模型选择

### 1. 项目与模型管理

- **多项目工作区（后端已支持）**
  - 支持创建新项目（填写项目名称、源语言与目标语言，当前支持中文与英文互译）以及在已有项目与内置 Naev 示范工作区之间切换。
  - 每个项目拥有独立的文件版本、图谱快照、记忆库与译文历史，互相隔离。
- **模型接口登记与按环节绑定（后端已支持）**
  - 支持登记多个兼容服务接口的模型配置（自定义名称、模型标识、服务地址、超时时间、密钥环境变量名）。
  - 在**项目设置**中，支持把六个本地化环节分别绑定到不同模型：
    1. 图谱信息提取
    2. 上下文证据筛选
    3. 主译文生成
    4. 审校与主动查证
    5. 问题定向修复
    6. 自然语言意图理解
  - 每个模型配置提供**「测试可用性」**按钮，可针对指定环节发起真实探针测试，确认该模型是否支持常规生成、结构化输出或工具调用。
  - **后端能力边界说明**：出于凭据安全边界，网页端不直接提交或保存明文密钥，密钥需预先配置在服务端环境变量中；此外，模型配置绑定在项目级别（创建任务时冻结生效），暂不支持在单次任务发起时临时覆盖模型；同时目前缺少在页面直接查看“服务端各个密钥环境变量是否已配置就绪”的状态接口。

### 2. 文件导入与变更预检

- **支持格式与范围（后端已支持）**
  - 新建项目支持导入 **CSV、Excel（XLSX）与 UTF-8 PO** 文件（单文件 16MB、10 万行以内）；内置 Naev 示范工作区支持导入其专用简体中文 PO 文件。
- **字段映射与导入前差异预览（后端已支持主体逻辑）**
  - 上传表格文件时，允许配置工作表名、ID 列、原文列、保留译文列（仅在导出回写时保留原列结构，不作为参考泄露给翻译模型），以及游戏上下文属性列映射（如所属文档、场景、对话块、剧情分支、阶段、说话人、听话人、话题、额外要求）。
  - 正式确认入库前，提供**「导入预检」**步骤：展示本次操作会**新增多少条、原文修改多少条、保持不变多少条、移除多少条、跳过多少行**，并明确提示“原文发生变化或被移除的条目，其依赖的旧记忆和旧图谱会自动失效”。
  - **前端衔接与边界说明**：后端直接接收列映射配置参数，未单独提供“读取表格工作表与列名列表”的服务端接口；前端可在浏览器本地轻量读取文件首行/表名辅助用户下拉选择，或提供表单填写。

### 3. 资源列表与待译范围选择

- **位置级条目展示（后端已支持）**
  - 即使多条文本的英文原文完全相同，只要出现在不同剧情分支、不同文件或不同对话位置，界面上都会作为独立条目展示其文件路径、行号或位置坐标、复数形式及上下文属性，避免误合并。
- **搜索与筛选（后端部分支持）**
  - 支持按所属文件和关键词（匹配原文或上下文）分页搜索资源，勾选目标条目发起单批任务（自定义项目单任务最多 64 条，Naev 示范区最多 12 条）。
  - 当需要翻译整份文件或超过单批上限的大量条目时，支持切换为**「自动分批连续翻译」**：设定每批条数与单批最大模型调用次数，由后台按顺序逐批推进。
  - **后端能力边界说明**：自定义项目的资源查询接口目前支持按“文件名”和“原文关键词”过滤，暂未提供按“剧情分支、说话人、当前译文状态”直接过滤的服务端参数。

## 三、 模块二：知识图谱构建与记忆/图谱可视化

### 1. 分批构建图谱

- **预算可控的建图操作面板（后端已支持）**
  - 导入项目文件后，支持在页面发起建图任务，可配置：
    - 是否启用模型提取实体与关系（关闭时仅发布基础结构快照，不消耗模型调用）；
    - 是否全量重建（默认仅对新增或原文有变更的条目做增量提取）；
    - 每批条目数、最大允许调用次数、单批输入/输出篇幅限制。
  - 若当前未提取条目所需的批次超过用户设置的最大调用次数，系统会直接返回明确提示，告知至少需要多少次调用，避免跑到一半因预算不足中断。
- **进度跟踪与断点重试（后端已支持）**
  - 展示建图已完成批次数、总批次数、每批提取的实体与关系数量，以及未通过结构校验被拒收的条目提示。
  - 若某批因网络或模型超时中断，支持点击重试从断点批次继续，不浪费已完成批次结果。

### 2. 图谱可视化

- **局部实体关系浏览器（后端已支持）**
  - 支持按图谱快照版本、关键词、指定节点、指定剧情分支进行查询，在画布或关联列表视图中展示实体节点、文本出现位置节点及其关系连线（如所属阵营、人物关系、实体定义等）。
  - 每个节点与关系边都展示当前**有效/失效状态**，点击后可在侧边详情卡查看该关系提取自哪句游戏原文（含引文片段与所在文件行号）。
- **后端能力边界说明**：
  - 图谱目前为**只读可视化**，不支持在界面上直接人工新增、修改或删除图谱节点和连线；
  - 后端图谱查询以分页切片返回局部图谱，目前未提供全图总览统计接口（如各类型实体总数统计）或把“实体节点与对应术语/角色笔记”打包聚合的单一接口，前端可通过分别请求组合展示。

### 3. 记忆可视化与维护

- **项目记忆库（后端已支持）**
  - 分为**「已生效记忆」**与**「待审核草稿」**两个清单展示：
    - 已生效记忆包括批准的术语约束、说话人风格笔记、以及经过审校验证的历史译例；
    - 支持编辑在浏览原文或复核时**人工起草记忆草稿**（术语需指定原文词面、规定译法、是否强制使用，并选中原文中的一句真实片段作为依据；角色笔记需关联到已知说话人）。
    - 支持对草稿执行**「批准生效」**，或对已过时的记忆执行**「退役失效」**（需填写原因）。
  - **后端能力边界说明**：记忆列表接口目前全量返回项目下的已批准记录，暂不支持服务端分页与关键词检索；另外，目前工作台自动翻译流程只会把通过审校的译文写入译例记忆，尚未自动生成待审核的术语/风格草稿供人工勾选审批。
- **术语变更影响预演与级联维护（Naev 示范区已支持）**
  - 针对 Naev 示范工作区提供独立的**「术语维护沙盒」**：
    - 支持新增术语规则或修订已有术语规则（可限定到所选条目、指定文件或指定剧情分支）；
    - 提交修改前先执行**「影响预演」**：在不发布新规则、不调用大模型的前提下，列出所有受影响的现有译文，并分类标明原因——需要复查、已满足新词无需修改、处于作用范围外、因人工锁定而跳过、或因关联旧证据失效而需人工介入；清晰标示出哪些条目是通过“引用了含该术语的证据”被级联发现的；
    - 确认应用后，自动为需要复查的条目发起轻量复核任务；完成后若发现不妥，支持在规则与相关译文未受后续变更冲突的前提下**追加式回滚**到改前版本。
  - **后端能力边界说明**：上述完整的术语变更影响预演、自动局部复查与回滚链路目前仅绑定于 Naev 示范工作区；普通新建项目目前通过前述“项目记忆库”进行术语的批准与退役。

## 四、 模块三：双通道翻译发起与人机协同交互

### 1. 界面点选 + 对话框双通道发起（按现有单轮意图架构设计）

- **通道一：界面勾选 + 表单发起（后端已支持）**
  - 在资源列表中勾选目标条目后，可直接选择动作（如「翻译并导出」「仅翻译」「仅审校已有译文」），并在**「补充说明/编辑要求」**栏填写自然语言要求（例如：*“保持海盗粗犷口吻，飞船名保留英文不译”*），还可按需设置本次任务最大调用上限。
- **通道二：Agent 对话指令框（后端已支持）**
  - 在全局对话输入框直接下达自然语言任务，支持附带当前界面选中的条目范围作为默认上下文，例如：
    - *“把选中的这几条翻译成简体中文并导出，注意人称代词统一用‘你’。”*
    - *“帮我检查这几条译文有没有漏掉上下文设定。”*
    - *“解释一下刚才那条‘皇帝之拳’为什么这么翻。”*
    - *“把术语 Landing 改成 着陆，看看会影响哪些句子。”*
  - **执行计划确认流**：Agent 解析出结构化意图链（翻译 / 审校 / 术语更新预演 / 解释 / 导出）、目标资源、语言方向与补充要求后，任务按解析结果进入排队与执行，界面清晰展示当前计划步骤流（如 `翻译 → 导出`）。
  - **后端能力边界说明**：沿用“每次指令独立解析为一个任务”的单轮交互机制，暂不设计跨任务连续记忆上下文的多轮闲聊对话窗；同时，在自然语言里直接写文件名、原文或条目 ID 时需精确匹配，暂不支持如“帮我选中所有第三章带船长的句子”这类模糊条件选词。
- **独立文本快译入口（后端已支持）**
  - 保留快捷文本粘贴框，支持中译英与英译中单段文本的草译、格式校验、人工微调及结果下载，与正式项目资源库隔离。

### 2. 缺失信息澄清与运行中人工干预

- **结构化澄清表单（后端已支持，替换当前直接展示原始文本片段的方式）**
  - 当自然语言指令缺少目标范围、缺少目标语言、或者提到的名称匹配到多个条目产生歧义时，任务暂停在**「等待补充信息」**状态。
  - 前端不再直接展示原始文本片段，而是根据后端返回的缺项明细动态渲染可点选控件：
    - 缺意图时：提供意图多选/排序确认；
    - 缺目标或有同名歧义时：直接列出候选资源原文及所属文件/位置供勾选消歧；
    - 缺术语对时：弹出原词、新译法、旧译法填写框。
  - 补充完成后立即从断点接续原任务，避免重复解析或丢失上下文。
- **运行中优雅暂停与中途改要求（后端已支持）**
  - 任务执行期间可随时点击**「暂停任务」**，界面显示“正在等待当前条目/批次安全完成后暂停”。
  - 暂停后弹出**「补充新要求」**输入框，编辑可修改或补充后续条目的翻译指示再点击「继续」，新要求只作用于尚未开始的条目，已完成的条目版本保持不变。
- **安全取消与异常重试（后端已支持）**
  - 支持随时取消未结束的任务；当模型调用出现超时或返回结果状态未知时，界面明确提示“前次调用结果未明”，由编辑勾选确认后再执行重试，防止无意中重复触发外部计费请求。

### 3. 审校透明化（“透明玻璃箱”）与专注式复核台

- **审校与查证过程追溯面板（后端已支持）**
  - 任意条目旁均可点击**「查看依据」**，分层呈现本次翻译与审校的完整过程，全部使用通俗表达：
    1. **候选范围 vs 实际输入**：对比“系统检索到的所有可能参考”与“模型最终实际看到的参考内容”，明确标识哪些属于系统强制要求遵守的硬术语规则（模型不可擅自丢弃），哪些是筛选后的软性参考，避免编辑误判模型幻觉来源。
    2. **审校 Agent 主动查证记录**：展示审校环节是否调用了辅助查证工具（查图谱设定 / 核对具体证据 / 查术语库 / 查历史译例 / 查说话人笔记）、实际查了什么关键词、查到了什么片段；若检索词命中了其他剧情分支或未授权文件的内容而被系统拦截，前端醒目展示**“已自动屏蔽 N 条越界/他分支命中”**。
    3. **审校结论与转人工原因**：展示审校 Agent 给出的判定（通过 / 需修复 / 需人工接手）及具体理由；若经过了自动修复与复审，按时间顺序列出各轮结果。
- **专注式人工复核工作台（后端已支持）**
  - 任务进入**「待人工复核」**状态时，采用三区块协作布局：
    - **待处理条目列表**：支持只筛选需要人工处理的问题项（待人工接手、版本冲突、已锁定、执行失败）；支持随时点击**「接受已完成部分」**，把已通过条目直接放行至导出阶段，剩余疑难项明确标记为排除。
    - **原文与译文对照编辑区**：并排显示原文、游戏位置信息、待修改译文草稿、以及系统给出的问题原因；编辑在输入框改动文字时，前端同步做基础格式提示（如占位符变量缺失、换行数量不一致、首尾空格差异、缺失当前生效的强制术语），提交「批准译文」时由后端再做严格终检并写入新版本。
    - **版本控制与溯源提问**：对已生成的译文支持**「锁定 / 解锁」**（锁定后不会被后续自动重译或术语批量修订覆盖）和**「回滚到指定历史版本」**；若对某句为什么这么译有疑问，可点击发起「解释依据」任务查看对应版本的历史输入与审校回执。
- **后端能力边界说明**：
  - 复核界面的「解释依据」通过创建一个 `explain` 任务获取结果，适合查看历史静态证据，但尚不支持在单条输入框旁进行即时流式问答或“按新语气一键重生成这一句草稿”。

### 4. 导出预检与原格式交付

- **导出前体检与冲突解决（后端已支持）**
  - **Naev 示范区**：支持导出前预演检查，显示通过验证并即将写回的条目数、所有未纳入导出的条目及其明确原因（如未通过验证、人工关闭跳过、共享键存在未批准项等）、以及 Gettext 格式与编译检查结果；当同一个 PO 原文键下对应多个出现位置且产出了不同已批准译文时，前端列出各版本的译文内容与版本号，由编辑点选最终采用哪一版，再执行安全下载与变更报告导出。
  - **自定义项目**：支持按原导入文件直接导出（CSV/XLSX 保留非目标列、其他工作表及公式结构；PO 保留原文件头、注释与非目标条目，并执行格式检查），同时查看或下载被排除条目的清单报告。

## 五、 模块四：Agent 自我进化（RSI）闭环设计

本系统的自我进化**不重新训练或修改底层大模型的权重参数**，而是通过“采集人类真实改译反馈 → 汇总共性盲区 → 调整策略与辅助规则 → 隔离沙盒对比测试 → 门禁发布与回滚”实现安全、可追溯的持续改进。

### 1. 日常工作流中的反馈采集

- **复核改译顺手收集（后端已支持）**
  - 在复核工作台修改并批准一条译文时，编辑器旁提供**「补充反馈原因（可选）」**与问题分类标签，提交批准时系统自动把修改前后的文本对照、所在任务与快照信息记入反馈库。
- **独立问题登记与实体别名纠偏（后端已支持）**
  - 对于已经处理完毕的历史条目，也可以在证据详情或进化中心补充登记一条反馈，选择所属问题类别：
    - 译文纠偏、检索遗漏、提示指令问题、记忆问题、查证技能流程问题、工具参数层问题。
  - 若发现审校 Agent 查图谱时因为拼写差异没查到设定（例如原文写 `Emperors Fist`，图谱标准名是 `Emperor's Fist`），可直接在该条反馈中填写**「实体别名对照（查询词 → 标准实体名）」**。

### 2. 问题模式聚合与候选方案编辑

- **反馈汇总与重复模式识别（后端已支持）**
  - 进化首页列出全部历史反馈记录，并重点展示系统自动聚类的**「重复失败模式」**（例如同一实体别名在两条及以上不同游戏文本中反复引发漏查）。
  - 编辑勾选一条或多条关联反馈后，点击**「创建策略候选方案」**。
- **四维受控策略编辑器（后端已支持）**
  - 候选方案允许调整以下四类安全边界内的配置，并实时显示各部分版本指纹变化：
    1. **提示与交互模板**：追加审校 Agent 首次查证源图时的补充注意事项；调整转人工原因的展示话术模板（需包含 `{reason}` 占位符，可选 `{occurrence_id}`）。
    2. **工具层增强**：整理并维护实体别名自动扩展映射表（从勾选的反馈中自动带入无冲突的别名对）；设置单次工具查询返回结果条数上限（1 条或 2 条）。
    3. **查证技能触发范围**：勾选允许启用查询扩展的问题场景（如歧义、证据缺失、术语核对、上下文缺失）。
    4. **拟定术语预挂载**：支持选择 Naev 工作区中处于“预览状态”的术语变更方案，先放进后续沙盒对比测试里看影响，而不急着正式发布术语。
  - **后端能力边界说明**：目前候选修改内容需由人工参考反馈记录手动填写配置，后端暂未提供“由 AI 自动归纳反馈并代写策略草案”的接口；反馈聚类目前也主要围绕重复别名，其他类别暂按列表人工筛选。

### 3. 隔离沙盒对照测试（防泄漏验证）

为了防止“改好了这几句，却把其他句子改坏”或“拿做过的题考自己导致虚假提升”，候选方案必须经过严格的双集隔离对比测试：

- **双数据集选择与防泄漏保护（后端已支持）**
  - **反馈案例集**：只能选用本候选方案关联的反馈条目，验证原来的痛点是否解决（可标注期望命中的证据或期望审校结论）。
  - **独立验证集**：从历史有完整审校轨迹的任务中选择未参与反馈的条目进行防退化测试。前端在选择界面**主动过滤并禁止勾选**与反馈案例来自同一出现位置、同一源文件或同一独立文本的内容。
  - **后端能力边界说明**：单次测试请求最多包含 8 条案例，且目前需要用户从历史已完成任务中选择具体条目传入，后端暂未提供“一键自动推荐合规不重叠验证集样本”的接口。
- **双模式对照回放（后端已支持）**
  - 在临时沙盒副本中并排运行“现行生效策略（修改前）”与“候选策略（修改后）”，支持两种测试模式：
    1. **历史记录回放**：不调用大模型，直接复用历史工具回执，验证新的转人工展示模板与基础硬规则检查是否全部通过。
    2. **策略对照回放**：固定相同的历史初稿和初始上下文范围，重新执行查证工具以对比检索改善；可选开启**「真实模型复核」**（在相同历史模型与预算约束下重新跑一遍首次审校判定）。
- **对比体检报告（后端已支持）**
  - 汇总展示改动前后的核心对比指标：证据命中率、证据缺口解决数、越界引用次数、硬规则违规次数、不安全提交数、转人工率、模型调用数、消耗篇幅与耗时；并可逐条展开查看前后查询串、命中证据和审校判定的详细差异。

### 4. 发布闸门、版本谱系与安全回滚

- **阻断式发布闸门（后端已支持）**
  - 前端把后端的发布强制校验规则可视化为一张「上线前检查清单」，全部满足后才允许点击**「正式发布」**：
    - 反馈案例与独立验证案例的记录回放必须全部通过，无越界引用与不安全提交；
    - 如果改动了别名、查证条数、技能范围、术语或审校指令，对应的策略对照回放必须全部通过；
    - 如果改动了检索或技能范围，必须在标注样例中观测到实际的证据缺口改善；
    - 如果改动了审校补充指令，必须在真实模型下完成策略回放且标注了预期审校结论；
    - 如果挂载了拟定术语方案，该术语方案必须先在术语维护流程中完成正式批准。
  - 若评估后认为收益不明显或风险偏高，也可选择**「保留现行策略（归档本次候选）」**。
- **策略版本线与一键回滚（后端已支持）**
  - 展示从初始基线到历次正式发布的版本演进列表及每次发布理由；后续新建的所有翻译和审校任务都会自动锁定并记录创建时生效的策略版本。
  - 一旦发现当前线上策略效果不如预期，支持在版本列表中点击**「回滚至上一版」**并填写回滚理由，系统追加一条恢复前序配置的新发布记录，历史任务与审计轨迹不受破坏。
  - **后端能力边界说明**：后端已记录每个任务创建时冻结的策略版本，但暂未提供按策略版本横向聚合长期线上通过率或人工改译率的统计报表接口。

| 功能域 | 首版前端可直接落地的能力（后端已就绪） | 明确标为“边界/暂不强求”的当前后端限制 |
| --- | --- | --- |
| **项目与模型** | 多项目创建、6 角色模型绑定、模型连通/工具探针测试 | 密钥必须在服务端环境变量配置；不支持页面传明文密钥或单任务临时覆盖模型 |
| **文件与资源** | CSV/XLSX/PO 上传、字段映射配置、变更预检、位置级查看、全文件自动分批 | 表格表头预览在前端本地处理；资源列表服务端仅支持按文件名与关键词过滤 |
| **图谱与记忆** | 预算可控增量/全量建图、断点重试、局部关系浏览器、记忆草稿/批准/退役、Naev 术语影响预演与回滚 | 图谱为只读；P4 术语级联预演目前仅限 Naev 示范区；翻译暂不自动生成待审术语草稿 |

| **Agent 进化 (RSI)** | 工作流内嵌改译反馈、实体别名标注、重复模式汇总、四维策略编辑、双集隔离对照回放、防泄漏校验、门禁发布与追加回滚 | 仅涵盖策略/工具/提示/知识进化，不涉及模型权重训练或训练样本导出；验证集样本需手动勾选、策略修改由人工拟定 |
