# P3 · 简易工作台与原生 PO 交付

工作台是一个最简 React + TypeScript 页面，分为资源、任务、复核和交付四块。前端通过同源 FastAPI 访问已有任务服务，P0/P1 的工作流和 P2 的 SQLite 任务、版本与事件仍由后端管理。页面、样式与构建配置集中在 [web](../web/index.html)。

## 启动

在 `submission/agentdesign` 中执行。沿用 [运行说明](../README.md) 安装 Node 与 Python 依赖。

```bash
uv pip install --python .venv/bin/python -r requirements-api.txt
npm --prefix pi ci
npm --prefix web ci
npm --prefix web run build
.venv/bin/python run_api.py --offline
```

浏览器打开 `http://127.0.0.1:8766/`。离线模式用于操作验证。配置 `DEEPSEEK_API_KEY` 后省略 `--offline` 即使用真实网关。工作目录可用 `--data-dir` 指定。

1. 上传简体中文 UTF-8 PO，搜索英文原文或上下文，按资源位置勾选本次条目。每批最多 12 个出现位置。
2. 留空任务要求时执行翻译并导出，也可输入自然语言。任务显示 SSE 进度与条目结果，刷新后恢复最近的任务。
3. 打开证据以分别查看初始召回、实际模型输入、主动查询和 Reviewer 判定。编辑待复核译文并批准时，后端重新执行硬检查。
4. 校验并下载 PO 与变更报告。若同一 PO 键有不同的已批准译文，选定一个已批准版本再重新校验。接受部分交付时，报告保留排除原因。

## PO 接口与范围

| 接口 | 用途 |
| --- | --- |
| `POST /po-uploads?filename=…` | 上传 UTF-8 PO 原始字节，返回文件哈希、条目数和映射数 |
| `GET /po-uploads/{id}/entries` | 按原文或上下文查询和分页，返回 occurrence ID 与源位置 |
| `POST /jobs` | 带 `upload_id` 和所选 ID 创建任务，目标受该 PO 作用域限制 |
| `POST /jobs/{id}/po/preview` | 校验原生导出，返回变化、排除和冲突 |
| `POST /jobs/{id}/po/download` · `/po/report` | 导出 PO 和变更报告，接收与预览相同的 `choices` |

用 `(msgctxt, msgid, msgid_plural)` 精确匹配冻结 Naev 快照，保留不同源位置的 occurrence ID。未知条目继续保留在原始 PO 中。简体中文的复数目录使用 `msgstr[0]`，英文单复数源位置都保留。它们若产出不同译文，共用的槽位需要编辑明确选择。选中的共享键仍有未批准的出现位置时，保留上传版本并在报告中列出。

上传文件及已有中文译文只用于本机匹配、回写和报告，模型读取被冻结源图的源侧数据。导出只更新获批的译文字段及对应 fuzzy 标记。保留文件头、注释、来源、上下文和非目标条目的原始字节。完成回写后重新解析 PO，具备 GNU Gettext 时运行 `msgfmt --check`，并加载编译的 MO 验证修改项。缺少 `msgfmt` 时，报告标记为 `parser_only`。

## 实际验收

使用 [Naev 固定快照的原始简体中文 PO](https://github.com/naev/naev/blob/123fdc1be96d350fdff04cd2f61e2c66c99badd5/po/zh_Hans.po)。输入 SHA-256 与研究快照登记值一致，共 24,192 条含废弃记录的物理条目，绑定 36,568 个源出现位置。

- Chrome 离线验收上传完整 PO，选择着陆提示与伊尼奥斯修道院，查看后者的主动查询，刷新后恢复待复核状态。人工改译并批准后，下载的 PO 仅改变两处译文字段，变更报告列出两个 v1。产物位于 `runs/p3-browser/`。本轮浏览器闭环使用离线模型回执。
- 导出通过 GNU `msgfmt --check`，编译的 MO 可由 Gettext 加载并返回两条更新译文。验收覆盖 Gettext 格式与运行时查找，Naev 游戏内加载和游玩仍待验证。
- 7 项现有及新增测试通过。专项覆盖上下文区分、复数槽位、共享键冲突选择、CRLF、fuzzy、废弃条目保留以及部分交付时共享键排除。
