# P4 · 术语维护与版本验收

沿用本地工作台、SQLite 和 P1 审校器。页面新增简易的“术语维护”区。可登记或更新指定规则，预览其影响，确认后查看修订工作及回滚。调用入口见 [工作台启动说明](../README.md)。

## 预览与确认

- 术语用英文原文精确匹配，作用域可按 occurrence ID、原生文件或已知分支限制。更新规则时同时检查旧、新作用域。计划合并术语词面命中、旧术语记忆引用、实际输入中的源图证据和已提交译文的反向依赖。
- 预览保存规则版本、知识版本、源图哈希及受影响条目的版本和锁状态。报告显示 `needs_review`、`no_change`、`out_of_scope`、`locked` 或 `insufficient_evidence`。提供旧译法时生成待核对的逐条替换建议。预览不发布术语和译文，也不调用模型。
- 确认时重新核对计划和版本。新术语作为已批准的硬规则进入后续任务的 ContextPack。只把需要复查的条目交给 P1，从现有译文开始。硬检查或语义复核发现明确问题才修复。提交前再次检查术语、人工锁、译文版本和知识版本。范围外及已满足的条目保持原版本。
- 单个计划最多排入 12 条复查任务，其余记录为待人工处理。已锁定的译文保留在当前版本。新的导出会排除违反生效规则或仍待重新验证的版本，并记录原因。
- 回滚需要修订任务先结束或取消。回滚前检查规则仍为当前版本、受改译文未被锁定或更新，并检查恢复的译文适用当前其余术语。通过后追加规则版本与译文版本，保留原有历史和审计。

| 接口 | 用途 |
| --- | --- |
| `GET /glossary` | 读取当前规则及知识版本 |
| `POST /maintenance/preview` | 传 `source`、`target`、可选 `previous_target`、`rule_id` 和 `scope`，返回持久化的预览 |
| `GET /maintenance/{id}` | 查看影响原因、前后版本、审校任务状态和逐条模型调用数 |
| `POST /maintenance/{id}/apply` | 确认发布；必要时创建后台修订任务 |
| `POST /maintenance/{id}/rollback` | 追加回滚版本 |

应用和回滚需要 `Idempotency-Key`。过期的计划需重新预览。规则作用于冻结 Naev 数据以及该工作目录中的译文。M6 的依赖、作用域和重新核对路径参考了 [PR #8](https://github.com/March2424/LLM_Project/pull/8)，本实现沿用工作台的版本与审校接口。

## 验收

固定 Naev 源样本与受控离线译文用于术语从「降落」改为「着陆」的验收。计划包含一条应改、一条已满足、一条范围外和一条人工锁定记录。预览前后业务版本和记忆记录数量一致。应用后只有需改项产生一个新译文版本，消耗 4 次模拟模型调用。核对了新译文的原生记忆依赖指向已批准的新规则。

专项验证还覆盖旧、新作用域切换，实际证据引出的锁定级联项，知识和译文并发变化导致的过期计划，以及追加回滚后恢复历史术语和译文。测试入口见 [维护验收测试](../tests/test_maintenance.py)。本轮通过离线模型回执验证 P4 状态、模型选择边界和提交行为，真实网关下的维护翻译质量尚未评测。

另用 Chrome 操作简易工作台，确认预览显示四类条目，应用后只有需改项从 v1 升为 v2，回滚追加 v3 并恢复「准许降落。」。浏览器验收记录保存在 `runs/p4-browser/acceptance.json`。
