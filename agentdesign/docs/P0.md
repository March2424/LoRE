| 项目 | 本轮记录 |
| --- | --- |

| Naev 源图 | 冻结开源 Naev `123fdc1be96d350fdff04cd2f61e2c66c99badd5`、图快照 `graph`、源库 SHA-256 `51c774cd54c195d9c6995291ef8fc7899d6d96df5bcea497efce490d841695b3`。清单锁定四条待译及总共 53 个允许的源 ID，已逐条与源侧 CSV 的英文及上下文核对。参考译文独立存放。每次运行从只读源库备份，并在副本中生成知识快照、读水位及 TM。 [Naev 来源与许可](../../game-localization-agent/data/naev/snapshot-123fdc1/ATTRIBUTION.txt) · [固定清单](../configs/naev-p0.json) |

| PR #8 | 对照基线 `d8be34cae4f5bd65483568956de76064be733e32` 与 PR head `6991d2ae339825c298412f1d5d5c7c421f811646`。沿用 `selector(pool, hints)`、硬检查后审校和绑定当前输入提交的接口。P0 由工作台的 LangGraph 编排，使用三态 Pi 判定和真实网关用量。PR 的补检索、软记忆更新、恢复和维护对应后续阶段。 [PR #8](https://github.com/March2424/LLM_Project/pull/8) |
| 运行依赖 | Python 3.14.7、LangGraph 1.0.10、OpenAI Python 2.26.0、Node 24.14.0、Pi Agent Core 和 Pi AI 1.5.2。角色提示词及研究模块哈希随轨迹保存。 [依赖](../requirements.txt) · [Node 锁文件](../pi/package-lock.json) |
| 模型和预算 | 网关请求模型 `deepseek-v4.1-flash-1017`，响应返回 `deepseek-v4-1-flash-261017`。业务侧采用 UTF-8 字节数作为软证据的保守计数代理，预算 1,024，最多 8 项。模型实际 token 用量来自网关并单列。 [配置](../configs/p0.json) |

选择器按模型返回顺序构建包。候选 ID 越界、重复、超预算或调用失败时，使用固定排序，硬规则仍由同一打包器直接保留。修复后重新运行硬检查和 Pi 审校，审校回执绑定草稿哈希与上下文哈希。P0 只把通过的译文写进本次运行的记忆。
