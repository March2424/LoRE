# P2 · 任务服务与 API 验收

FastAPI 在本机启动一个 worker，复用 P1 的 LangGraph 翻译和取证。工作目录中的 `workbench.sqlite` 保存冻结源图副本、任务、条目、版本、事件与调用账本，`checkpoints.sqlite` 保存 LangGraph 检查点。队列随进程重启恢复。任务等补充或人工复核时有明确的暂停状态，前端可以重新读取任务详情和续订 SSE。

## 启动

在 `submission/agentdesign` 中执行。先按 [运行说明](../README.md) 安装 Python 和 Node 依赖。

```bash
uv pip install --python .venv/bin/python -r requirements-api.txt
.venv/bin/python run_api.py --offline
```

服务监听 `127.0.0.1:8766`，交互接口为 `/docs`。命令行支持 `--port`、`--data-dir`、`--db`。默认的离线工作目录为 `runs/p2-offline/`。配置 `DEEPSEEK_API_KEY` 后运行 `.venv/bin/python run_api.py` 使用真实模型和独立工作目录 `runs/p2-service/`。每个工作目录同一时间只允许一个 worker。P2 的资源目录来自 P0/P1 清单中的五条 Naev occurrence，支持 occurrence ID、原文标签和文件筛选，分支筛选以源数据实际字段为准。

## API

所有 POST 操作提供 `Idempotency-Key`。相同键和相同请求复用回执，换内容需使用新键。前端以 `GET /jobs/{id}` 返回的 `status`、条目、证据、数量和 `next_actions` 为准。

| 调用 | 行为 |
| --- | --- |
| `GET /resources` | 查看可选资源，支持 `file`、`branch_id` |
| `POST /jobs` | 提交 Naev 资源任务或 `source_text` 文本任务。`text` 用于自然语言指令，也可指定单个 `intent` 或有序 `intents`。 |
| `GET /jobs/{id}` | 查任务、阶段、条目、缺失信息、版本、预算和产物 |
| `POST /jobs/{id}/continue` | 补充目标、语言、意图或术语等字段，继续原任务。空补充或全为原值时返回 `clarification_requires_new_information`。 |
| `POST /jobs/{id}/cancel` · `/retry` · `/accept-partial` | 取消、重试，或关闭未决项并接受已完成部分 |
| `GET /jobs/{id}/items/{step}/{occurrence_id}/evidence` | 查模型实际上下文、Pi 审校与只读工具回执。回执仍放在 `source_lookups` 字段中，使用 `name` 区分工具。 |
| `POST /jobs/{id}/items/{step}/{occurrence_id}/approve` | 批准收到的草稿或提交人工改译。请求带 `expected_version` 和 `expected_draft_hash` |
| `POST /jobs/{id}/versions/{occurrence_id}/{action}` | 用 `lock`、`unlock` 或 `rollback` 明确操作本地译文版本 |
| `GET /jobs/{id}/events` | SSE 进度，按 `Last-Event-ID` 或 `after` 续读 |
| `GET /jobs/{id}/files/{name}` | 下载 `report.json`，导出阶段结束后可下载 `export.json` |

| 意图 | 结果 |
| --- | --- |
| `translate` | 运行 P1 闭环，提交当前验证通过的译文，保留待人工项 |
| `review` | 审校已批准译文或请求附带的草稿，给出问题、证据和建议稿 |
| `propose_update` | 按当前译文版本生成术语影响预览。已知旧译法时可给 `term.previous_target` 生成候选改动 |
| `explain` | 依据指定任务版本的实际输入清单和审校回执解释译文 |
| `export` | 返回通过校验的 JSON 译文、版本和排除原因。有翻译前置步骤时先等该步骤结束 |

自由文本由 Pi 发起一次结构化 DeepSeek 请求，Python 根据实际授权目录解析目标。结构化请求直接进入计划。人工批准会重新检查格式和适用硬规则，版本变更或人工锁会阻止写入。回滚追加一个指向已验证历史译文的新版本。调用账本在请求前记录预算占用，响应一到即保存回执；恢复时复用已完成结果。无法确认网关结果的调用要由编辑显式选择是否重试。版本冲突需要用最新版本创建新任务。

## 双向文本任务

`POST /jobs` 带 `Idempotency-Key`。`source_text` 保存原文，`target_lang` 接受 `en` 或 `zh`。也可指定 `source_lang`，提供其中一个语言时推导另一方向。只提供原文和方向时，默认翻译并导出。

```json
{"source_text":"飞船已抵达 {station}。","target_lang":"en"}
```

改用英文原文和 `"target_lang":"zh"` 即可英译中。每条文本任务冻结独立源快照并使用同一套草译、硬检查、修复、人工复核和 JSON 交付。任务详情和导出都带语言方向。Naev 源图和中文 PO 资料保留在原有资源流程中。

离线集成验证覆盖两个方向的批准和导出，以及中译英的占位符缺失修复、换行和首尾空白。实际 DeepSeek 双向翻译质量待验证。[任务测试](../tests/test_task_api.py)

## 已执行验证

- **真实网关**，提交 “Translate into Simplified Chinese and export.”。Pi 识别出翻译、导出，任务因缺资源暂停。补充已授权的着陆提示后，同一任务完成并导出一条 v1，排除项为零。含意图识别共 4 次真实调用。工作目录为 `runs/p2-live-api/`，验收快照为 `acceptance.json`。
- **HTTP 与持久化**，离线实测补充资源及语言、关闭并重开 worker、恢复待复核草稿，并发重复批准产生同一个 v1。过期草稿哈希和锁定状态均阻止批准。验证了 SSE 续读、导出依赖和审校、解释、术语预览出口。调用账本专项检查确认已完成回执可重放，结果未知时不会自动重发。[API 测试](../tests/test_task_api.py)
- **版本与部分交付**，测试了部分接受后仅导出已完成条目，验证过期版本拒绝写入、回滚追加 v3，以及取消待补充任务。
- **阶段范围**，P2 的导出为已批准译文 JSON。原生 PO 交付与浏览器工作台属于 P3，术语发布和级联维护属于 P4。当前是本机单编辑者服务。
